# Releasing EnVault

macOS only for v1. Releases are built by `.github/workflows/release.yml` when you push a tag.

## One-time setup

Repository secrets (Settings > Secrets and variables > Actions):

| Secret | What it is |
| :-- | :-- |
| `CSC_LINK` | Developer ID Application certificate as a base64 `.p12` (`base64 -i cert.p12 \| pbcopy`) |
| `CSC_KEY_PASSWORD` | Password of that `.p12` |
| `APPLE_ID` | Apple ID used for notarization |
| `APPLE_APP_SPECIFIC_PASSWORD` | App-specific password for that Apple ID |
| `APPLE_TEAM_ID` | Your 10-character team ID |
| `ENVAULT_UPDATE_URL` | `https://` folder that serves updates, e.g. `https://example.com/envault/updates` |

Enable **Security > Private vulnerability reporting** on the repository (see `SECURITY.md`).

## Cutting a release

1. Update `CHANGELOG.md` and bump `version` in `package.json` (`npm version 1.0.0 --no-git-tag-version`).
2. Merge to `main` with CI green.
3. Tag and push: `git tag v1.0.0 && git push origin v1.0.0`.
4. The workflow tests, builds arm64 and x64, signs, notarizes, verifies (`codesign`, `spctl`, `stapler`), smoke-tests the app, and drafts a GitHub release with the artifacts.
5. Upload to the update server, **zips and `latest-mac.yml` last**: copy `*.dmg`, `*.zip`, `*.blockmap`, then `latest-mac.yml` into the folder `ENVAULT_UPDATE_URL` points to. Publishing `latest-mac.yml` is what makes installed apps see the update.
6. Publish the download page link to the `.dmg` and the SHA-256 (`shasum -a 256 EnVault-*.dmg`).

## Rollback

Delete or replace `latest-mac.yml` on the server with the previous version's file. Installed apps only move to what that file names.

## Local checks

- `npm run pack` builds an unsigned `.app` into `release/mac-arm64/` (no certificate needed).
- `npm run smoke:packaged` launches it on a throwaway profile and checks the vault opens, the version matches, and the renderer has no Node access.

- A dual-architecture build leaves the x64 copy of the native SQLite module in `node_modules`, which breaks `npm test` and `npm run dev` on Apple Silicon. `npm run build:mac` restores it automatically. If you run `electron-builder` by hand, finish with `npx electron-builder install-app-deps`.

## Things that must not change after the first public release

- **`appId`** (`com.rizkyamanatama.envault`): changing it breaks update continuity and keychain access.
- The `publish.url` host: installed apps look for updates there.

## Notes

- The packaged app stores data in `~/Library/Application Support/envault` (same as development builds) but uses its own Keychain entry. If you open a **development** vault with a packaged build, the key cannot be read and EnVault will ask for the recovery passphrase. Set a recovery passphrase in your development vault first (Settings), or use Export and Import to move it.
- The app icon in `build-resources/` is a placeholder generated by `scripts/generate-placeholder-icon.py`. Replace `icon.icns` (and `icon.png`) with the real icon before a public release.
- Fuses (`scripts/afterPack.cjs`): Node-as-runtime and Node CLI/inspect flags are disabled in packaged builds, so `--inspect` and `ELECTRON_RUN_AS_NODE` do not work there.
